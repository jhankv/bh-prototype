# Banhaten audit — start here

Four short reports, each one a single story. Read whichever concerns you; none
of them needs the others.

| Report | What it covers |
| --- | --- |
| **Keyboard** | `toolbar` `button-group` — focus management, and why it is missing |
| **Direction** | `kbd` `tooltip` `Table` `Breadcrumbs` `PageHeader` — RTL and bidi |
| **Forms** | `input` `badge` `avatar` — flags that do nothing, vocabularies that disagree |
| **Data** | `Table` `PageHeader` `pagination` — counts, labels, and untranslated strings |

## How an entry is named

After its component, numbered in the order we found it — `toolbar-1`, `badge-2`.
The name carries the subject before you reach the text, and it survives a
retitle, which matters because entries cite each other.

**Status** is one of three:

- **FIXED in `banhaten-proposed`** — a patch exists; run `banhaten diff` to see it
- **open** — a defect with one right answer, not yet patched
- **Question** — more than one answer is reasonable, and the choice is yours

We patch only when the component already promises the behaviour and the code
does not deliver it. Anything that would change behaviour for existing consumers,
add API, or pick between different products is left as a Question. Taking those
decisions silently is how an audit loses its standing.

**Every screen is a faithful reproduction of a real product.** Without that, any
defect can be answered with "that layout is not real". Where a screen needed
something Banhaten does not ship — navigation lists, prose, page tabs — that is
plain markup, so a defect there would be ours and not yours.

## Verified good

Checked deliberately and found correct, so nobody re-checks them.

- **RTL layout**: column order, sort affordances, filter chips, search field and
  its icon, pagination controls, page header actions and breadcrumbs all mirror.
- **Theming**: `brown` and `sharp` change brand colour and radius with nothing
  hardcoded leaking through.
- **Dark mode**: status colours, row separators and surfaces hold.
- **Arabic typography**: IBM Plex Sans Arabic loads and renders at table density.
- **Alignment**: `align: "end"` resolves to the left edge in RTL for numerics.
- **Already carrying `dir="auto"`**: `tag`, `badge`, `button`.

## Investigated and rejected

Knowing what is *not* broken is what keeps the rest credible.

**`Table` does not draw its own progress bar.** It defines a local `Progress`
function, which looked like a second implementation. It is not — the function
wraps `components/ui/progress` with three preset props:

```ts
import { Progress as ProgressPrimitive } from "@/components/ui/progress";
```

A convenience wrapper, not a fork. No divergence is possible.

**Currency renders as `$US ١٢٬٤٨٠٫٥٠` in RTL, not `US$ …`.** Not a defect.
`Intl.NumberFormat("ar-EG")` emits the mark, then digits, then `US$`, and `$` is
bidi-neutral, so the Unicode algorithm correctly places it left of `US` in an RTL
paragraph. Verified by reading the raw code points.
